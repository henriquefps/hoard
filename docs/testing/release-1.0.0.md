# Release 1.0.0: integrated end-to-end run

- **Date**: 2026-11-08/09
- **Build**: debug APK (the e2e run), then the signed R8 release APK (`hoard-1.0.0.apk`)
- **Device**: Android emulator, API 36.1 (Android 16) arm64, Google Play image, 1080×2340 @ 420 dpi,
  Android System WebView 134
- **Server**: the disposable Samba in `docs/testing/samba/` (Docker, 256 MB / 1 CPU), with real
  JPEG/PNG photos, two H.264 MP4 videos (12 MB, 144 MB) and a 200 MB file added

The UI (PR #3) and the native plugin (PR #4) were built in parallel against the contract; this was
the first run of the real app against a real server.

## Setup

```
emulator ──10.0.2.2:4450──▶ tools/proxy.mjs (killable, throttled) ──▶ smb-a :4445
         ──127.0.0.1:4446─▶ adb reverse ──▶ proxy :4451 (throttled) ──▶ smb-a :4445
         ──100.100.1.1:445 (nothing there: a dead "Tailscale" address)
smb-b :4447 (a second Samba instance, different server GUID)
```

- Machine with three addresses: `10.0.2.2:4450` (local), `127.0.0.1:4446` (local),
  `100.100.1.1` (Tailscale, dead).
- Route failures were simulated by killing the proxy (connection closed), `kill -STOP` on it
  (connection stays open, nothing answers: the "Wi-Fi gone" case), `docker stop` (server down),
  pointing the proxy at smb-b (another server on the same address), and `svc wifi/data`.
- The debug WebView was driven over Chrome DevTools Protocol (`tools/cdp.mjs`: find an element,
  tap its coordinates with `adb shell input`); system screens (SAF picker, permission prompt,
  notification shade) with `adb shell input` and `uiautomator dump`. The release build (no WebView
  debugging) was driven by coordinates from screenshots.

## Bugs found and fixed

| #   | Bug                                                                                                                                                                                                                                                          | Fix                                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `TransferService.retry()`: when the native start failed synchronously, `markFailed` wrote `bytesDone: 0`, losing the resume offset (known).                                                                                                                  | `markFailed` takes the bytes to keep; `retry` passes the row's `bytes_done`. Unit test added.                                                                                                |
| 2   | Video thumbnails never appeared: `hasThumbnail` listed only image extensions, so the UI never asked, although native renders video frames.                                                                                                                   | `THUMBNAIL_EXTENSIONS` matches `Thumbnailer.kt` (images + mp4/m4v/mov/3gp/mkv/webm); the mock thumbnails videos too; a small play badge marks video thumbnails. Contract doc updated.        |
| 3   | A browse call on a silently dead connection took **90 s** before the UI could reconnect: after smbj's 30 s request timeout, dropping the session ran TREE_DISCONNECT and LOGOFF inline, each waiting another 30 s. The folder stayed on skeletons meanwhile. | Dropped sessions close on a background thread; TREE_DISCONNECT/LOGOFF only when the connection is alive; per-request timeout 30 s → 20 s. Measured after the fix: 20 s, then the next route. |
| 4   | A transfer on a silently dead route kept showing "Downloading · 4.3 MB/s" for ~30 s before failing over (each pipelined READ waited the full 30 s).                                                                                                          | `PipelinedFileReader` in transfers uses a 15 s stall timeout: no answer means the route died, so retry/fail over (resume is exact, a false alarm only costs a reconnect).                    |
| 5   | The free-space check before a download never ran for normal folders: external storage refuses the roots query (`SecurityException`, needs `MANAGE_DOCUMENTS`), so `NO_SPACE` could only surface mid-transfer.                                                | Fallback to `fstatvfs` on the destination document just created.                                                                                                                             |
| 6   | System bars ignored the app theme: "Dark" on a light phone left white status/navigation bar strips; "Light" on a dark phone left dark ones.                                                                                                                  | New local plugin `SystemUi` (`SystemUiPlugin.kt` + `src/plugins/systemUi.ts` + `src/lib/theme/systemBars.ts`) paints the bars and sets icon contrast from the resolved theme.                |
| 7   | Rename selected the whole name including the extension (Radix auto-focus calls `select()` after the dialog's own selection).                                                                                                                                 | The base-name selection is re-applied after focus (only while the name is untouched).                                                                                                        |
| 8   | `bun run android:debug` fails in a fresh worktree: `android/local.properties` (git-ignored) is missing.                                                                                                                                                      | Documented in CLAUDE.md (not a code change).                                                                                                                                                 |

## Not verified / known limitations

- **No physical device.** Everything ran on the emulator; real Wi-Fi roaming and Tailscale were
  simulated (proxy kill/SIGSTOP, `svc wifi`, `svc data`).
- **WebView ≥ 140 insets path** (see the table): not exercised; the emulator image ships WebView 134.
- Once, right after the process-death test, a folder took ~20 s to list; it did not reproduce
  (cold starts list in 0.2 s). Most likely a dead session, which bug 3's fix now bounds at 20 s.
- A host that accepts TCP but never answers SMB (hung `smbd`) costs the 20 s request timeout plus
  the connect timeout before the next route; a route that is really gone fails the 1.5 s probe.
- Native notifications follow the **system** language, not the in-app language setting.
- Sizes differ slightly between the notification (Android, 1000-based: "13 MB") and the app
  (1024-based: "12.4 MB").
- A cancelled transfer shows the bytes it had reached although its partial file was deleted.
